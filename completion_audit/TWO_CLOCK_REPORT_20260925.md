## Implemented authority boundary

- `btc15_information_native_v1.py`: opt-in native export. The stored PR36 source is untouched. Its pinned AST gains exactly one observer call after successful completion of the original try-body. Removing that expression yields the exact original AST. The observer serializes at most 32 completed candle rows and 4,096 already-committed ticks (normal native retention is smaller), original clocks, contract, fixed target and model identity. Exceptions clear only the information anchor. It never changes native history, globals, gates, outputs or side effects. Its work is included before the original loop computes its remaining sleep budget.
- The loopback bridge copies the existing quote owner and BRTI delivery owner under nonblocking locks. It never calls quote `consume`, BRTI `accept/select`, upstream APIs, or a strategy/protection function. Accepted quote-event membership is retained under lock and detached outside it; original proof files are never overwritten. New frame source time and receipt cutoff are explicit; exchange and original BRTI receipt clocks are preserved.
- `btc15_information_v1.py`: a separate-process evaluator uses only the original pure `_fair_build_snapshot` arithmetic and the hash-verified frozen fitted model. It derives disposable feature frames from committed history. There are no fast accumulated BTC ticks, partial candles, persistence counts, entry births, shadow-log rows or lifecycle transitions. No rejected whole-loop projection is used.
- `btc15_information_service_v1.py`: a bounded, loopback-only GET API and independent information worker. Only genuinely newer source observations trigger another evaluation. Duplicate polls, later receipt/check clocks, repeated queries and sequence-only acknowledgements do not. Source regressions, conflicting identities and same-contract target changes fail closed. Exact immutable input/output bytes are retained by identity; eviction never falls back to the latest proof.
- Capture, completed publication and every display response recheck causality, original BRTI age ≤5.0 seconds, existing quote/BTC limits, fixed contract, current owner and health. A one-second infrastructure health lease bounds disconnected rendering. WAIT nulls all dependent probabilities, prices and context; it does not carry a last-good assessment forward.
- `btc15_information_view_v1.js`: optional, uninstalled display adapter. It uses monotonic request/receipt/render times and conservatively charges full round-trip elapsed time against the server's deadline. Slow delivery, device UTC skew, disconnected rendering or an old-page token cannot renew freshness. Information and native output remain separate namespaces, with the original native object unchanged.

`TWO_CLOCK_FIELD_AUTHORITY_20260925.md` classifies every new exposed field and the relevant existing domains. No information field is EARLY/SCALP/FINAL readiness or HOLD/CAUTION/PROTECT/EXIT/FLIP advice. Descriptive probability is computed from the last native Coinbase sample; this minimum architecture intentionally adds no faster upstream polling. BRTI/quote context can update between native BTC observations, with all source timestamps visible.
