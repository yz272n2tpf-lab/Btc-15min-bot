IMPLEMENTATION — paths relative to the new repository
1. candidates/early_rebuild_20261012/underlying_history.py (new)
   Observation contains only BTC/BRTI values, joint cutoff/receipt, original per-feed
   source and receipt clocks, record identities, feed IDs and epochs. It contains
   no contract identifier, target, window, quote, origin or management field.
   UnderlyingHistory.ingest owns a bounded 135-second delivered prefix; Snapshot
   supplies an immutable view. No sorting of events, interpolation, backfilling,
   synthetic clocks or missing-price reconstruction occurs.

   Validation requires finite positive values, ordered source<=receipt<=cutoff
   clocks for each component, a cutoff delivered by decision time, nondecreasing
   receipts, strictly advancing joint observations with gaps <=15 seconds, stable
   source identities/epochs, BTC age <=10 seconds and BRTI age <=5 seconds. These
   per-source limits follow the retained native directional source gates; the
   existing feature endpoint allowance and gap limit remain 15 seconds.
   Component freshness is also checked at the actual current decision/tick.
   Repeated publications cannot change their values or receipt timestamps.
   Exact duplicates do not add or refresh an observation. Conflicts/out-of-order
   samples invalidate the buffer; a gap or source/epoch change starts a fresh
   segment that must independently accumulate legitimate longer context.

   Native-clock, fixture and retained-observation proxy domains remain distinct.
   Fixtures cannot qualify retained decisions. The proxy requires healthy=True
   but never treats that flag as proof of original clocks; absent component clocks
   remain None. Its use requires an explicit diagnostic-only opt-in.

2. candidates/early_rebuild_20261012/continuation.py (modified)
   causal_vector has an optional underlying_history Snapshot input. Only price
   history is substituted. Current ASK, runway and target-based range floor come
   from the current validated contract observation. The six ordered feature
   definitions and arithmetic are unchanged, including the 30-second windows.
   When no new input is supplied, the old same-contract computation remains.
   Explicit empty/invalid independent input fails closed; it does not fall back.
   Future observations, endpoint mismatches and missing 120-second context return
   explicit unavailable errors rather than estimated features.

   ContinuationEstimator requires the independent-history provenance schema in
   addition to existing digest, method, code, support and chronology checks. Its
   inference accepts the dedicated Snapshot. underlying_history.py participates
   in code identity. No artifact coefficients or calibration were changed.

3. candidates/early_rebuild_20261012/continuation_engine.py (modified)
   Owns a separate copied UnderlyingHistory, ingest_underlying, and availability-
   only continuation_context. Contract rollover does not clear this separate
   buffer. Invalid history clears continuation score availability without changing
   onset or manager state. Cached scoring cannot bypass new history validation.
   A tick cannot refresh an old component's freshness. Scoring cadence is unchanged.
   Proxy histories are rejected by this engine interface.

4. candidates/early_rebuild_20261012/engine.py (INSPECTED; BYTE UNCHANGED)
